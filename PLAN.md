# Wisp plan and status

The status below is as of 2026-11-06. Testing approach: decision logic lives in `WispCore` and is written test-first. The app layer only wraps system APIs and SwiftUI. The current suite is 734 tests. For what comes next, see `docs/REVIEW.md`.

Fixed after E: plan approvals from the notch did nothing, because Claude Code ignores a bare allow for `ExitPlanMode`; the reply now echoes the plan back as `updatedInput`. `AskUserQuestion` showed as Needs you with no card (it gets one since the agent cards round); Allow All covers tool calls only. Sessions whose agent quit without SessionEnd kept counting until the 6 h prune; the helper now sends the agent's pid and start time (`AgentProcess`, walking up past shells) and the hub ends a session within 15 s of its process going away. A process is trusted only once two reports name it, so a launcher that runs each hook and exits is never taken for the agent, and a resumed session's new process replaces the old one. A question answered in the terminal sends no hook, so new spend in the status bar while a session waits marks it working again (the first real cost replacing an estimate doesn't count). A denied plan tells Claude to keep planning. Sessions show their terminal's app icon in the pill and the shelf, from the bundle ID the helper already sends; the details action is named after the app. Sessions from an older helper still rely on the prune.

Untested: `WispAgent/SocketSend.swift` (the helper's fire-and-forget send) has no automated test because the helper target isn't in the test bundle; it was checked by hand against Wisp Dev. Everything the helper renders is tested in `StatusBarRenderer`. `AgentHub`'s alert wake-up (`scheduleAlertCheck`, which only moves when the next limit does) has no app-layer test; the limits it waits for come from `AgentAlerts.nextCheck`, which is tested, and it was checked by hand.

Dropped from the agent cards round: todo progress. Claude Code 2.1.319 has no todo tool on current models (TodoWrite and the Task tools are both missing, even with `CLAUDE_CODE_ENABLE_TASKS=1`), so there's nothing to read. A limit chip in the pill was also dropped: the 80%/95% notices and the details cover it without crowding the pill.

Not checked by hand yet: the expanded preview and "Deny with a reason…" (built and unit-tested, not clicked through), the question bar in an open shelf, and the question card in private mode. The usage limit notices were checked with a sample snapshot, not a real near-limit session.

Not checked by hand yet (orb and ring): tearing the real notch off and docking it back, the Agents sub-ring against a live request, the mouse button and hold-to-pick, per-app rings, dropping files on the ring, and the Ring settings pane. Nothing was tried on a Dynamic Island Mac. Not built from the plan: the orb's halo doesn't show timer or limit progress (an activity turns the orb into a pill anyway), double-click to dock, holding Hyper+R to pick, shaking a file to open the ring, and display info in `wisp status`. Fixed after review: sub-ring items out past neighbouring segments couldn't be reached, tear-off could start from a drag meant for a window under a corner or bottom shell, an aborted tear-off cleared the display's position, the mouse button failed silently without Accessibility, and the ring had no shortcut without Hyper. Left from review: the orb's panel is resized on every drag event, and Ring settings rows are keyed by position.

Next for Dynamic Island Macs: once macOS 27.3 ships, publish agent, approval, timer and limit activities as system Live Activities (a widget extension target and App Intents for Allow and Deny, opt-in, behind `#available`), so they show in Apple's island or the menu bar. Then touch: larger targets and taps on touch-screen Macs.

Ideas for later, from a look at other notch and Mac utility apps (behaviour only): jump to the exact terminal tab or tmux pane; Gemini CLI, Cursor, OpenCode and Copilot CLI support; a sound per agent event; a per-session spend cap; session history kept across relaunches; "always allow" rules written to `permissions.allow`; screenshots and OCR into the tray (needs Screen Recording, so ask first); a downloads progress activity; OCR on clipboard images (Vision, local); more system stats (battery cycles, disk, network); window snapping (Accessibility); a charging animation; lock screen widgets.

Seen in the 2026-11-06 sweep, not fixed yet: spend is written to UserDefaults up to four times a second; the socket file isn't removed on quit; `sendDraft` leaves the draft on the clipboard; tcsh, nu and pwsh aren't in the shell list, so their agents' processes aren't confirmed; whether an approval answered in the terminal closes its card before the 110 s timeout needs a manual check.

Seen while testing E, not yet investigated: after a display was unplugged, both notch panels stayed idle while an agent activity was queued (`wisp status` listed it) until another activity forced a redraw. Reproduce by changing displays with an agent running, and compare with `main`.

Decided against the original brief: no `ModelLimits` table (Claude Code's snapshot and Codex's rollouts both report the window size); no current-tool segment in the terminal bar (the helper is stateless); Codex gets no terminal bar (it has no external status line command, openai/codex#17827).

## Not done

- **HUD extras:** keyboard backlight (private CoreBrightness) and DDC brightness and volume on external displays both need private APIs, so they wait for a decision. VPN pill.
- **Shelf size:** done as a zoom of the shelf content; widgets keep fixed layouts rather than reflowing.
- **Screen recorder.**
- **Lock screen player:** built with public APIs only; whether macOS shows it over the lock screen is untested.
- **Distribution:** release-please keeps a release PR on `main`; merging it tags a draft release, and `release.yml` builds the DMG, the Sparkle zip and `appcast.xml`, uploads them and publishes. Wisp updates itself with Sparkle. Releases are signed with the self-signed "Wisp Dev" certificate until there's a Developer ID (the script already supports notarisation).

## Verify by hand

1. **Animation and shape.** Click the notch: it opens to 451 pt, the content expands out of the notch with the surface, then the nav pill settles in.
2. **External display.** A drawn notch sits flush with the top edge (no margin). Switch to the island style in Settings › Notch.
3. **System overlays.** Volume keys show a wing with a green bar. Brightness shows yellow. Caps Lock shows On/Off.
4. **Tray.** Drag a file from Finder onto the notch: four tiles appear. Drop on Keep, then open the Tray tab.
5. **Clipboard.** Copy a few texts, links and images, then press Caps Lock + V (or ⌥⇧⌘V).
6. **Now Playing.** Play in a browser (YouTube Music) or Music: artwork and a waveform show beside the notch.
7. **Closing.** The shelf content shrinks into the notch with the surface, and the nav pill rides up into it.
8. **Clicks outside the shelf** reach the app underneath.
9. **Bubbles.** Play music, then start a timer: the music pinches off into a bubble right of the pill. Start a Claude Code prompt too: it splits off on the left. Click a bubble: it swaps into the pill.
10. **Drag out.** Drag a file over the notch, then away without dropping: the shelf closes.
11. **Themes.** Settings › Appearance › Theme: Aurora shows violet into teal on the Tinted surface; Outline draws a rim on the open shelf.
12. **Swipes.** Two fingers down on the closed notch opens it; sideways on the music pill skips. Scrolling lists inside the open shelf never closes it.
13. **Headphones.** Connect AirPods: a pill shows them with battery levels.
14. **Position.** Settings › Notch › Position. Try each: the shelf grows out of that edge, the bottom island stays above the Dock, and on the left or right a timer shows upright (ring over time) with bubbles above and below. The menu bar stays clickable with a top-corner island.
15. **Mini player.** Drag it by its background anywhere, including onto another display; reopen it and it is where you left it.
16. **Appearance.** Settings › Appearance: each preset changes the preview and the shell together. Ears show beside the idle notch and hide behind a live activity. Try confetti. Turn on the pet and leave the Mac idle two minutes: it dozes. Export a look, change it, import it back. Give a profile a look and switch to it.
17. **Mic pill.** Plug in a USB mic with headphones and play music through it: no pill. Record in QuickTime: "Recording" shows. Unplug: it goes within a second or two.
18. **Closing cards.** `make run`, then post `com.ayomideodewale.wisp.debug.card` (a Debug build hook): point at the card and it stays with a × in the corner; click the × to close it; two fingers up closes it too; leave it and it goes after its remaining time (at least 1.5 s).
